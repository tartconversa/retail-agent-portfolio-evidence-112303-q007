# 使用说明与评估口径

本应用服务于集团数字化团队的投资委员会、业务负责人与数据治理团队，用来：

1. **持续登记**候选 Agent 场景及其验收口径；
2. **比较组合**：在有限预算与共享实施容量下选出试点次序；
3. **管理阶段决策**：登记、推进、释放、暂停、修订、停止，并可回看结果；
4. **区分证据等级**：把已观察收益、假设收益与缺少基线的部分分开呈现。

所有资料均为本地合成数据，不含真实主体信息；程序只用 Python 标准库。

---

## 一、快速开始

```sh
# 评估全部 36 个场景，输出文本报告
PYTHONPATH=src python3 -m retail_agent_portfolio_evidence evaluate --data data

# 机器可读报告（适合存档或接入看板）
PYTHONPATH=src python3 -m retail_agent_portfolio_evidence evaluate --data data --format json > report.json

# 查看单个场景的证据、闸门与价值口径
PYTHONPATH=src python3 -m retail_agent_portfolio_evidence show SCN-034 --data data

# 运行测试
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

在 Windows PowerShell 中，把 `PYTHONPATH=src` 换成 `$env:PYTHONPATH="src"`，其余相同。

安装为包后（`pip install -e .`）可以直接使用 `python -m retail_agent_portfolio_evidence`，无需设置 `PYTHONPATH`。

## 二、决策流程与角色

| 步骤 | 角色 | 命令 | 作用 |
| --- | --- | --- | --- |
| 1. 组合评估 | 投资委员会 | `evaluate` | 依据预算与共享容量排序，给出入选集合与未入选原因 |
| 2. 登记验收 | 业务负责人 | `register` | 确认流程愿意改变，写入可量化指标、方向、阈值、测量起点 |
| 3. 阶段决策 | 投资委员会 | `decide release/advance/hold` | 释放已批准阶段的未释放资金，或推进阶段 |
| 4. 结果回看 | 全体 | `review` | 用**登记时**的验收口径判定达标/未达标/数据不足 |
| 5. 未达标处理 | 投资委员会 | `decide pause/stop` | 暂停未释放资金；已释放与已形成合同金额保留 |

决策历史写入 `registry/decisions.jsonl`（追加式），场景与验收口径写入 `registry/scenarios.json`（原子替换）。
因此后续任何结果都能回到原始场景定义与当时的政策版本查询。

### 示例：完整闭环

```sh
REG=registry

# 业务负责人登记验收口径：单位工时不高于 0.03 小时/件，从 2026-Q2 起计
PYTHONPATH=src python3 -m retail_agent_portfolio_evidence register SCN-034 \
  --data data --registry $REG --metric unit-hours --direction at-most \
  --threshold 0.03 --unit hours/case --measured-from 2026-Q2 \
  --actor "业务负责人-产品" --rationale "约定试点单位工时上限"

# 投资委员会释放试点阶段资金
PYTHONPATH=src python3 -m retail_agent_portfolio_evidence decide release SCN-034 \
  --data data --registry $REG --actor "投资委员会" \
  --rationale "试点设计完成，释放第一阶段" --stage pilot

# 结果回看
PYTHONPATH=src python3 -m retail_agent_portfolio_evidence review --data data --registry $REG

# 若未达约定指标：暂停仍未释放的资金（已释放部分自动保留）
PYTHONPATH=src python3 -m retail_agent_portfolio_evidence decide pause SCN-034 \
  --data data --registry $REG --actor "投资委员会" \
  --rationale "未达约定指标，暂停未释放资金"
```

## 三、评估口径（重要）

### 1. 三类价值严格分开

| 价值 | 含义 | 是否计入组合排序 |
| --- | --- | --- |
| **已观察价值** | 试点测量可复核、覆盖范围可比时的保守年值 | 仅当口径可比时计入；本资料中全部不可计入 |
| **假设价值** | 基线人工成本 × 政策折减率，未经试点证实 | 展示，不直接排序 |
| **风险调整价值** | 假设价值 × 证据置信度 × 治理系数 × 业务承诺系数 × 就绪系数 | **是**，组合排序用此列 |

本仓库的合成资料中，试点业务量（季度约 500～2,300 件）与月度基线（1,240～9,640 件/月）口径不可比，
且换算后的试点单位工时**几乎全部高于基线**。因此：

- 报告不会把"看起来很大的节省"当作已实现收益；
- 这些场景的"已观察年值"显示为**不可计入**，表内以"观察Δ单位工时"呈现方向；
- 与假设方向相反的场景，风险调整价值再打 **50%** 折扣，并单独列出提示。

这正是需求强调的"不能仅按演示效果或节省工时的单一估算排序"。

### 2. 基线口径

- 基线单位工时 = `baseline_hours / monthly_volume`（小时/件）。
- 试点期间若为季度（如 `2026-Q1`），业务量先除以 3 换算为月度，再与月度基线比较。
  无法识别的期间标签会标记为 `PERIOD_BASIS_MISMATCH`，不猜测长度。
- 试点月度换算业务量低于基线的 50% 或高于 300%，标记 `SCOPE_VOLUME_MISMATCH`，
  观察值只作方向参考，不货币化。

### 3. 证据等级

| 等级 | 触发条件 | 置信度（政策默认） |
| --- | --- | --- |
| 已观察 | 单次测量完整、期间可比 | 0.85 |
| 部分测量 | 任一记录 `measurement_state=partial` | 0.55 |
| 测量冲突 | 同一 (期间, 数据版本) 出现多条矛盾测量，或状态不一致 | 0.30 |
| 缺少基线 | 记录为 `baseline-missing` | 0.20 |
| 无测量 | 没有试点记录 | 0.15 |
| 基线不可用 | 业务量或基线工时为 0 | 0.00 |

**冲突测量不做平均、不挑最大值**：取最保守的一条（单位工时最高）并降低置信度。
同一场景存在多次治理审查时，**以最新一次为准**，历史结论不叠加。

### 4. 闸门（不折算成总分）

每个场景分别检查 6 个闸门，报告逐项通过/未通过：

1. **业务负责人承诺**：`owner_state=sponsor-confirmed`（技术验证通过 ≠ 业务方承诺采用）
2. **数据治理结论**：最新审查不为 `revise`
3. **依赖系统就绪**：无 `blocked` 依赖
4. **存在未释放资金**：仍有可释放余额
5. **基线可计算**：月业务量与基线工时均大于 0
6. **验收口径已定义**：登记了指标、方向、阈值、测量起点

进入设计阶段要求 1–5 通过；**释放试点资金/推进阶段还要求 6**。

## 四、预算、容量与敏感性

- **启动成本** = 最早一个仍有未释放余额的资金阶段金额；后续阶段依赖试点结果，不预先占用预算。
- **已超额释放**（`released_amount > amount`）不产生额外预算额度；超出部分记入资料问题，
  计算预算占用时按授权金额截断。
- **共享实施容量**：每个场景占用其依赖所在共享组的能力单位，同一共享组总量不得超过政策上限。
  多个场景共用数据平台或审批团队时，靠这一约束体现。
- 组合选择使用确定性分支定界，在预算与容量双重约束下最大化风险调整价值；
  结果与输入顺序无关（有测试保证）。
- 输出包含**预算敏感性**（0.5×～1.5×）与**共享容量敏感性**（0.75×～1.25×），
  并标注相对基准预算"新增/移出"了哪些场景，用于回答"预算变化会影响哪些候选"。

## 五、资金与合同保留规则

- 已释放金额与已形成的合同**不可通过暂停追回**。
- `pause` 只针对未释放余额；若该阶段已全部释放，命令会拒绝并提示保留规则。
- 同一场景多次暂停不会重复扣减（登记日志累计已暂停额）。
- `stop` 只改变后续决策资格，历史记录与已释放金额保留，仍可查询。

## 六、政策参数

所有假设集中在 `config/policy.json`，改参数不需要改代码：

| 字段 | 含义 |
| --- | --- |
| `loaded_hourly_cost_cny` | 人工小时综合成本 |
| `assumed_reduction_rate` | 保守/基准/乐观三档折减率 |
| `evidence_confidence` | 各证据等级置信度 |
| `governance_factor` / `owner_factor` / `readiness_factor` | 治理、承诺、就绪折减系数 |
| `default_budget_cny` / `default_group_capacity` / `capacity_by_group` | 预算与共享容量 |
| `budget_sensitivity_multipliers` | 预算敏感性倍数 |
| `selection` | 各闸门是否强制 |

命令行可用 `--reduction conservative|base|optimistic` 切换折减档位，用 `--budget` 覆盖预算。

## 七、资料问题的处理原则

加载器区分两类问题：

- **结构错误**（缺列、非数值、孤立场景引用）→ 直接失败，因为没有可信修正口径。
- **业务语义异常** → 记录为数据问题并按保守口径处理，不静默修补。当前资料中可见：
  - `DUPLICATE_MEASUREMENT`：24 个场景同一口径有两条矛盾测量；
  - `OVER_RELEASED`：13 个场景存在超过授权金额的释放；
  - `GOVERNANCE_SUPERSEDED`：12 个场景有多次审查，取最新结论；
  - `PERIOD_BASIS_MISMATCH` / `SCOPE_VOLUME_MISMATCH`：期间与覆盖范围不可直接外推。

这些都会出现在 `evaluate --format json` 的 `data_issues` 与文本报告的"资料问题"段，
供数据治理团队判断授权与风险边界，而不是被当成零值或成功。

## 八、命令参考

```text
evaluate   评估组合（--budget, --reduction, --format text|json）
show       查看单个场景（证据、闸门、价值口径、验收、回看）
register   登记/修订验收口径（--metric, --direction, --threshold, --unit, --measured-from）
decide     记录决策 advance|hold|release|pause|stop|note（--amount, --stage, --actor, --rationale）
review     按登记口径回看全部场景
```

`--data` 指定 CSV 目录，`--policy` 指定政策文件，`--registry` 指定登记目录。
